Both communication buses from the ESP32-S3 to the Raspberry Pi 5 and the XT-S1
use \gls{uart} communication. For the XT-S1 sensor, Modbus \cite{modbus}
is implemented on top of \gls{uart}, for a safe, reliable connection.
The protocol used to set the servos in position is simple \gls{pwm}.
The 5V rail from the Raspberry Pi is used to supply power to the ESP32-S3 and
the XT-S1 sensor.
A separate 5V \gls{psu} unit is used for the servos alone, as they draw high
currents during startup and when moving the main axis, which would not
be supported by the 5V supply from the Raspberry Pi.

\subsection{Prototype's evolution}

The prototype 3D case was designed over many different iterations.
The final version of the case can be seen by the end of Chapter~\ref{cap:prop}.
The specific \gls{pn} of the servo was selected after the most common
TowerPro SG90 (9g Servo) showed unacceptable backlash and slack.

The Raspberry Pi 5 also took some effort to operate reliably.
Without officially recommended peripherals, the \gls{sbc} showed problems with:

\begin{itemize}
  \item Power supply instability.
  \item Thermal management.
\end{itemize}

Without warning, the \gls{sbc} would stop properly working or even shut down.
The Raspberry Pi operated reliably only when using the official
heat sink and \gls{psu}. The prototype includes a fan powered by internal 5V
\gls{psu} so there is always a constant air flow inside the 3D printed case.

\subsection{Drone system}

As shown in Figure~\ref{fig:5ckt}, the drone system's hardware consists of

\subsubsection{Raspberry Pi's OpenCV algorithm}

The \gls{opencv} role in the drone system is to simply identify an object meant
to be a test target. The drone system will then provide the direction of the
\gls{poi} to the pod system, receive the distance information, and log it.

The entire drone system relies on \gls{opencv}'s capabilities of identifying
a designated \gls{poi}. The algorithm developed for the tests is the most
basic logic for identifying a basic object on a contrasted landscape.

The selected target is a green laser pointer, for its ease to set static
and dynamic tests in very large surfaces without the need of motors or
complex automation. To identify a simple green bright dot on a wall or ground,
a Python algorithm executes these simple steps:

\begin{enumerate}
  \item Capture of a single camera frame.
  \item Filter the entire frame for given hue, saturation and brightness.
  \item Use the filtered image to generate a mask.
  \item Use the generated mask to search for the biggest shape.
  \item Find the center of the biggest shape.
\end{enumerate}

With this algorithm, the drone system will search for a green dot of defined
hue, saturation and brightness ranges, and point at the center of the biggest
compatible shape. This basic algorithm will be used for all three tests
described in the next section. This simple of a setup allows for precise
static tests, with single or multiple points, and dynamic tests.
All three different tests will point the \gls{poi}'s direction to the pod
system, then log the distances informed, and calculate all the metrics.

\section{The tests}

The following sections will explain in detail the three tests:

\begin{itemize}
  \item Static single-point test.
  \item Static multi-point test.
  \item Dynamic test.
\end{itemize}

To test a device that calculates distances based on a laser rangefinder
mounted on a gimbal, first
it is important to assess how accurate the laser rangefinder is. For
that, a static single-point test can be executed, measuring the distance to a
known, easy to acquire target.
After the rangefinder is tested, the gimbal
must be tested as well. A static multi-point test can check if the angles
requested by the drone system are being correctly set by the motors.
The target
can be any planar surface. Multiple points are requested as targets and any
error in this test will propagate into the reconstructed 3D geometry.
With both the rangefinder and
gimbal tested, the system must be tested against a moving target. A dynamic test
to measure the angular performance of the system can assess how fast the system
can acquire the target and if the system can
keep track of a moving target while measuring its distance.

\subsection{Accuracy}

Following the terminology of ISO~5725 \cite{iso5725}, accuracy is decomposed into
\emph{trueness} and \emph{precision}, as can be seen in Figure~\ref{fig:5acc}.

\begin{figure}[ht]
  \centering
  \includegraphics[width=0.7\textwidth]{5/img2}
  \caption{Accuracy: Trueness and precision}
  \label{fig:5acc}
\end{figure}

According to ISO 5725-1, the general term "accuracy" is used to describe the
closeness of a measurement to the true value. When the term is applied to
sets of measurements of the same measurand, it involves a component of random
error (\emph{precision}) and a component of systematic error
(\emph{trueness}, also called bias).
In this case, precision is the closeness of agreement among a set of results,
and trueness is the closeness of the mean of a set of measurement
results to the actual (true) value.

The mathematical definitions are very simple. For a given test,
$N$ consecutive measurements $\hat{d}_{i}$ are
acquired, with
ambient illumination, target reflectance, and temperature recorded throughout.
Trueness (B, for sample bias) is a simple difference between the
arithmetic mean value and the accepted reference value:

\begin{equation}
  % title for equation list
  \addequationtoentry{Definition of trueness}
  \label{eq:true}
  \bar{d} = \frac{1}{N}\sum_{i=1}^{N}\hat{d}_{i}, \qquad
  B = \bar{d} - d_{\mathrm{ref}}
\end{equation}

Precision can be mathematically expressed as both variance ($s^2$)
and standard deviation (s).
Variance is used in analyses that have multiple sources of
error, allowing for the multiple errors to be added together to compound
the total error of the system. As this project focuses on the distance
range-finder, standard deviation is more appropriate.
Both are defined as:

\begin{equation}
  % title for equation list
  \addequationtoentry{Definitions of precision}
  \label{eq:precise}
  s^2 = \frac{1}{n-1} \sum_{i=1}^{n} (d_i - \bar{d})^2, \qquad
  s = \sqrt{\frac{1}{n-1} \sum_{i=1}^{n} (d_i - \bar{d})^2}
\end{equation}

\subsection{Static single-point test}

The single-point static test characterizes the accuracy of the
range estimation module under controlled, time-invariant conditions. A flat
target of known reflectance is mounted perpendicular to the optical axis of the
sensor on a rigid fixture, and its distance is established by an independent
reference instrument of substantially lower uncertainty than the prototype's,
such as a calibrated laser distance meter or a precision linear
stage with a traceable encoder.

Multiple measurements are executed, and the standard deviation
and arithmetic mean are logged, spanning the specified operating range of
distances that the module is capable of measuring, 
to ensure the device's accuracy won't drastically
change within its range of operation. 
For this test specifically, the target-tracking function on the drone system
can be
disabled, for the gimbal can be manually pointed at a wall of known distance.
The other tests will need target tracking.

An important point in this test is that, even though \emph{trueness} can be adjusted
by a calibration process in firmware after the tests, to improve accuracy,
the \emph{precision}
of the overall system is mainly determined by the precision of the sensor, which in
this system's case, comes pre-calibrated from the manufacturer.
The standard deviation of the measured distances will mainly depend on
the chosen sensor, the luminous noise at the target, and the distance,
since the sensor has an optimal measuring range and becomes less accurate
at very close distances.
So in the end, the overall error can be minimized by compensating any
error in the trueness of the measurements.

The test is repeated for several
distances and target tilt angles to assess the dependence of the error on
incidence angle, and, where relevant, for several surface reflectances.

\subsection{Static multi-point test}

The gimbal, just as the laser rangefinder, will need to have its trueness
calibrated, and precision measured.
Just as with the rangefinder, the precision is a product of the
manufacturer's specifications, which can be found in the \gls{pn}'s datasheet.
What can be done regarding the servos is using a bias value to compensate for
any drift on the control circuit and any imprecision on the 3D parts that, with
the servo, compose the gimbal.
The point of the static multi-point test is to test the accuracy of the gimbal,
as well as the accuracy of the parallax-compensating algorithm.

The multipoint test evaluates the three-dimensional performance of the module
over its \gls{fov}. A planar target of known flatness, larger than
the footprint of the FoV at the test distance, is the ideal target.
First, the parallax-compensating algorithm is disabled, and a parallax-induced
error is expected. Different points are designated as targets in the wall, and
with a laser pointer coupled in the gimbal, the distance between the designated
target and the new point on the wall can be measured, to make sure that only
the parallax is affecting the pointing system.
The laser unit (red laser) attached to the gimbal is of a completely different
frequency from both the target designator (green laser) and the \gls{tof}
sensor (\gls{ir} laser), to avoid interference.
After that, the test is repeated, but with the parallax-compensating algorithm
enabled. Now, there should be no parallax observed between both red and green
laser points in the wall. Each point will have its performance analyzed
multiple times, so enough data can be logged to analyze the gimbal's accuracy.

\subsection{Dynamic test}

The dynamic test assesses the ability of the module to follow a moving target
and characterizes its temporal behavior, which static tests cannot capture.
Many characteristics of the system can be evaluated on this test:

\begin{itemize}
  \item Delay between target movement and pod movement.
  \item Distance measurement error induced by delay.
  \item Gimbal step response.
\end{itemize}

To test the latency between target movement and pod movement,
a designated target can be projected on a wall that has a sharp edge.
The prototype scans at several angular speeds, in both directions. If the angle
and range samples are misaligned in time, the apparent edge position shifts with
speed, and flips sign when the direction is reversed. The size of the shift
divided by the speed equals the latency, which can be corrected in software.

To test the impact of the target-tracking loop's latency over the measurements,
different scans can be executed over a simple wall. The system can scan the same
wall at commanded rates from about 10\% to 200\% of the servo's maximum, in steps.
For each run, the system records the cloud of points and then calculates
in post-processing a plane-fit
(a plane that would best align with the points), the residual (% no space
the average error from all the 3D points to the regression plane), and
the normal-vector error (the angle between the fitted normal and the true one,
from the reference wall-target).

With a target performing a very fast step in angle over a wall, the system can
log the response and later analyze the settling time, overshoot, and ringing.
For more information about the response of the system, a target moving on a
sinusoidal pattern can shed more light on the dynamic characteristics of the
system. Amplitude and frequency of the sinusoid can be changed, and multiple
combinations can be executed to map the system's behaviour.
